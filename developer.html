Developer API

Use the MP Works backend to query source-backed MPLADS work records, inspect evidence status, explore members and export a filtered scope.

Public read APIRead endpoints are available without an account. Evidence refresh, feedback and report routes have separate limits and validation.

Public route contract

Configured deployment

The production host is intentionally omitted from this public reference. Configure your application with VITE_MPLAD_API_BASE, then append the documented routes below.

Contract notes
Build with provenance
Keep official source fields, evidence availability and derived review signals separate in your own product.
Source-backedRecords retain links to the official MPLADS/eSAKSHI source.
PaginatedUse limit and offset; server-side limits are bounded.
Approximate mapMap coordinates represent districts, not precise project locations.
Review signalRisk index and Gemini findings prioritize human review; they are not fraud verdicts.

        
Endpoint reference
default
Swagger-style route reference. Expand a route for its description and safe GET test.

          

            
GET/api/healthHealth
Returns service status and API version. Use this for deployment smoke tests.

            
GET/api/projectsSearch projects
Paginated work search. Filter with query, state, district, house, term, category and status.
Example: /api/projects?district=Indore&limit=20&offset=0

            
GET/api/catalog/facetsFilter options
Returns available houses, terms, states, districts, constituencies, categories and statuses.

            
GET/api/catalog/metricsScope metrics
Returns recommended, sanctioned, ongoing and completed counts plus allocation and expenditure fields when available.

            
GET/api/projects/:idProject record
Returns a public work record with source metadata, location, status, amount and review-index summary.

            
GET/api/projects/:id/evidenceEvidence state
Returns evidence items, files, comparison, persistence state and the current review signal.
States include processing, analyzing, analyzed and not-available.

            
POST/api/projects/:id/evidence/refreshQueue evidence analysis
Starts source attachment retrieval and optional Gemini comparison. Returns 202; poll the evidence route.

            
GET/api/mpsMember directory
Returns paginated source-backed MP records with optional Wikimedia/Wikipedia portrait enrichment.

            
GET/api/mps/:id/projectsMember history
Returns a member's paginated project history. Supports the same project filters and sort.

            
GET/api/map/locationsMap locations
Returns matching district points and counts. Points are approximate because source records do not publish reliable project coordinates.

            
GET/api/exports/csv|excel|pdfExport scope
Downloads the current filtered project scope with source fields, review index, evidence links and official source URLs.

            
GET/api/methodologyMethodology and caveats
Returns risk language, methods, source metadata and limitations for responsible downstream use.

          

        

        
Analysis model
What happens after evidence refresh?
Attachment bytes+Source project fields->Sharp signals + SHA-256->Gemini REST comparison->Review priority
Gemini is called directly through Google's Generative Language REST API using generateContent. The backend sends a bounded project record and up to four image/PDF files as inline data, requests JSON output and labels the result as a human-review aid. The current implementation does not expose a fraud verdict.
