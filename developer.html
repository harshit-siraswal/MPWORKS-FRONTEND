Integration notes

A predictable contract for public data

Use the console to learn the response shape, then move the same request into your application.

01

Read the envelope

Most collection routes return data, meta for pagination and, where available, provenance for source context.

02

Start small

Use limit=5 while prototyping. Paginated endpoints cap the limit server-side so one request does not pull the entire catalog.

03

Respect the signal

Risk indexes and Gemini comparisons are review aids. Keep official source fields, derived signals and human decisions visibly separate.

04

Protect the service

Cache stable reads, retry only transient failures, validate user input and never place provider credentials in browser code.

How the system fits together

Source record → API → your product

01 MPLADS / eSAKSHI source→02 Normalized catalog and evidence metadata→03 Node REST API→04 Your dashboard, research tool or civic service

The API exposes public records and bounded derived fields. Evidence retrieval and analysis routes are asynchronous: a 202 response means a job was accepted, so poll the related status route before treating analysis as complete.
